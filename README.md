# My Time Tracker — голосовой трекер дня

Telegram-бот [@MHabitT_bot](https://t.me/MHabitT_bot): рассказываешь голосом или текстом, как прошёл день,
бот раскладывает это на дела по времени (полезное / быт / прокрастинация), задачи, привычки и напоминания
(ежедневные, разовые «завтра в 10», «после еды»). Понимает вопросы («что у меня сегодня?») и поправки
(«не каждый день, только сегодня», «нет, играла до 11») — видит день и предыдущее сообщение.
Первые 3 недели — фаза наблюдения (только статистика), потом события владельца уходят в его Google Календарь.

## Пользователи

- Владелец — первый id в `ALLOWED_USER_IDS` (остальные id там — тоже админы).
- Чужой человек жмёт `/start` → админам приходит заявка с кнопками «✅ Пустить / 🚫 Нет». Список и закрытие доступа — `/users`.
- У каждого свои записи, напоминания, привычки, «о себе» (`/about`, затем голосовое или текст — подсказывает распознаванию и разбору его слова; длинный рассказ бот сжимает до 1–2 предложений).
- Google Календарь — только владельца. Бэкап и `/users` — только админам (в бэкапе данные всех).
- Не-админу — не больше `DAILY_ENTRY_LIMIT` сообщений в день (квота Groq бесплатная и общая).
- `/deleteme` — человек стирает все свои данные.
- Записи всех хранятся на хостинге владельца, и он технически может их прочитать — об этом стоит честно сказать друзьям.

## Как устроено

| Часть | Файл |
|---|---|
| Запуск, планировщик (чекины 11:00 / 16:00 / 21:30, напоминания раз в минуту, по воскресеньям разбор недели в 20:00 и бэкап в 22:00) | `main.py` |
| Команды и обработка сообщений | `bot/handlers.py` |
| Голос → текст (Groq Whisper) | `services/stt.py` |
| Текст → дела / задачи / напоминания (Groq `openai/gpt-oss-120b`, запасная `gpt-oss-20b`) | `services/ai_parser.py` |
| Google Календарь | `services/calendar_api.py`, вход — `auth_calendar.py` |
| База SQLite | `database/db_manager.py` → `database/tracker.db` |

Команды: `/summary`, `/todo`, `/reminders`, `/remind 10:00 Выпить витамины` (или `сегодня 15:00 …`, `завтра 9:30 …`,
`… после еды`), `/habits`, `/plan`, `/limit`, `/about`, `/patterns`, `/deleteme`; админам ещё `/users`, `/backup`.

## Настройки (`.env`, в git не попадает)

```
TELEGRAM_BOT_TOKEN=...
ALLOWED_USER_IDS=123456789      # владелец (+ админы через запятую); без этого бот не запустится
GROQ_API_KEY=...
TIMEZONE=Asia/Bishkek           # один пояс на всех пользователей
DAILY_ENTRY_LIMIT=50            # необязательно: сообщений в день для не-админов
```

## Как устроен разбор сообщения (и почему он стабилен)

Модель (Groq `gpt-oss`) от раза к разу отвечает чуть по-разному, поэтому ей оставлено только **понимание**:

1. Модель переносит сказанное, ничего не вычисляя: `start`/`end` («с 8 до 10»), `duration_min` («полтора часа»),
   `ended_ago_min` («час назад»), `part_of_day` («утром»), `day` («вчера»). В подсказке — разобранные примеры.
2. `services/ai_parser.py` проверяет ответ по самому сообщению («назад» есть, а `ended_ago_min` нет; «каждый день»,
   а напоминание разовое; «?», а это не вопрос…) и при ошибке **один раз переспрашивает** модель. Температура 0.
3. `services/timeline.py` считает время кодом (через полночь, «до сейчас», без будущего) и приводит названия
   к справочнику («поела» → «Еда», «зал» → «Тренировка»).
4. Остальное тоже кодом: встреча → напоминание за 30 минут, «вечер в 10» → 22:00, «≈» у прикинутого времени,
   честная пометка, за какие дни есть записи.

**Перед каждым обновлением** прогоните проверочные фразы (нужен `.env` с `GROQ_API_KEY`):

```
python tests/eval_phrases.py --runs 3
```

Всё должно быть «3/3». Нашли фразу, на которой бот ошибся, — добавьте её в `tests/eval_phrases.py`
(ошибки, отмеченные пользователями кнопкой «👎», админ получает командой `/feedback`). Репозиторий публичный —
личное из чужих сообщений (имена, болезни, питомцы) заменяйте похожими нейтральными словами.
Только новые фразы: `python tests/eval_phrases.py --only стоматолог`.

⚠️ Тесты тратят ту же бесплатную квоту Groq, что и бот: у основной модели **200 000 токенов в сутки**,
одно сообщение ≈ 2 000 токенов (≈ 100 сообщений в сутки на всех), один прогон ≈ 30 000, `--runs 3` ≈ 90 000.
Гоняйте по одному разу (`python tests/eval_phrases.py`) и не в часы, когда ботом пользуются. Когда основная модель
исчерпала лимит, бот сам переходит на запасную и пишет владельцу.

## Хостинг (bot-hosting.net)

Кнопка «Перезапустить» **не** скачивает новый код с GitHub. Обновление:

1. Консоль → режим **Shell** → `git pull origin master`
2. «Перезапустить»

База `database/tracker.db` живёт только на хостинге. Копия приходит в Telegram каждое воскресенье в 22:00
и по команде `/backup`. Восстановить — загрузить файл через вкладку «Файлы» как `database/tracker.db`.

## Календарь

Каждый подключает **свой** Google Календарь командой `/calendar`: вход в Google → бот создаёт в его аккаунте
отдельный календарь «Трекер дня» (доступ `calendar.app.created` — остальной календарь бот не видит) и пишет туда
дела сразу. Правка и «Отменить» меняют и события. Ключи хранятся в таблице `google_calendars` и в бэкап не попадают.

Нужно в «Окружении» хостинга:

```
PUBLIC_URL=https://psdy3towcr.apps.bot-hosting.cloud
GOOGLE_CLIENT_ID=…            # Google Cloud → Clients → Web application
GOOGLE_CLIENT_SECRET=…
```

В Google Cloud у клиента «Web application» — Authorized redirect URI `PUBLIC_URL/oauth/google`;
приложение опубликовано (Audience → Publish app), иначе ключи живут 7 дней.
Бот слушает `SERVER_PORT` (его задаёт хостинг), домен хостинга проксирует туда.

Старый путь владельца (`auth_calendar.py` → `token.json` → основной календарь) остаётся запасным.
Без рабочего ключа бот не падает и не зависает — просто пишет, что календарь не ответил.
